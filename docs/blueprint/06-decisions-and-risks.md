# 06. Decisions, Risks and Repository Hygiene

## 6.1 Owner decisions

Most of these change numbers users see; D12 to D18 set how the work is run and what is
shown, and D20 sets what Gate A asks of scanned Arabic cells. Defaults below are implemented behind `configs/analytics.toml` so a decision can change
without code changes. Each decision needs
an owner sign-off before the Phase 1 exit gate.

| ID | Decision | Options | Recommended default |
|----|----------|---------|---------------------|
| D1 | Zero or negative denominators (negative equity for ROE, negative EBITDA for leverage, a loss year for cash conversion) | Return null with a flag, or compute with a flag | Margins: compute and flag `negative_base`, a setting of `configs/analytics.toml` (`negative_margin_denominator`, provisional; `null` is the alternative). Zero denominators: null with `undefined_zero_denominator`. ROE, net debt to EBITDA, cash conversion and every other ratio: null with flag `undefined_negative_denominator` |
| D2 | Averages when the opening balance sheet is missing | Use the closing balance with a flag, or null | Closing balance with flag `average_fallback_to_closing` |

| D5 | Interim periods | Annualize flows, or skip flow-to-stock ratios | Skip in v1 with flag `interim_not_annualized` |
| D6 | Identity-check tolerance | Fixed absolute, relative, or rounding-aware | Rounding-aware: `n x 0.5` reported units, where n is the number of addends |
| D7 | Industry scope for v1 | All issuers, or non-financial corporates | Non-financial corporates. Banks, insurers and Islamic financial institutions route to `needs_review` with flag `unsupported_industry_template` |
| D8 | Narrative audience | Credit analyst, equity analyst, business owner | Credit analyst: liquidity and leverage first, neutral tone |
| D9 | Base model after the bake-off | Section 01, 1.6 | Decided by the rule in 1.6 |

| D11 | A statement that prints no unit multiplier (`scale_missing`) | Hold it for review, or use it at scale 1 | Decided 2026-10-01: use it, as a warning and not a reason to hold, with a footnote wherever an amount depends on the assumption, carried through to the written summary ([13](13-unit-caveats.md)) |

Downloading full-precision weights and every other use stay forbidden. The conditions (rehearsal, disk preflight, stop rule and others) are the engineering meaning given to "very carefully", not the owner's words, and are in [01-constraints.md](01-constraints.md) 1.4 |
| D13 | When the `model_test` checkpoint runs (it freezes the `model_test` and `blind` pools, `eval/corpus/README.md` rule 5) | During week 2 or 3, or once at the end | Decided 2026-10-02: "when we're 110% sure that everything is done and correct". Consequence as stated here: the checkpoint is taken once, after all planned work is complete and every check passes, not in weeks 2 or 3; until then Gates A and B are reported on `dev` and on dry runs, marked "not yet measured on `model_test`" ([08](08-revised-plan.md), Gates)  Waiting for every gate result was superseded by D23 (2026-10-26) |

Not built yet: how such a filing is identified in the demo. The review step ([12](12-ingest-review.md)) holds a statement on failed checks and flags, and nothing there recognises a scanned Arabic filing that misses the gate. Superseded for gate scope by D21; no longer governs a gate |
| D15 | Two statements of one type on one page with the same periods and layout merged as one continuation (R35) | Refuse the merge, or accept it | Decided 2026-10-02, delegated by the owner: they must not be merged. A guard for balance sheets is built and tested on synthetic parts only; income statements are not covered and R35 stays open for that type. A low-confidence grid that would otherwise have continued a closed balance sheet is left unattached, with the reason recorded. The rest is in R35 of [11-ingest-structure.md](11-ingest-structure.md) |
| D16 | What Gate C is measured on before the checkpoint | The `model_test` pool now, or a holdout of whole issuers taken from inside `train` | Decided 2026-10-02, delegated by the owner, who asked for "the most optimal method of measurement for it until then" and, if held-out issuers are the only one, why and how the plan changes: held-out issuers are the only valid kind, because a company's labels repeat across years and editions, but the pool need not be `model_test`. Gate C is measured, per source and never pooled, on a hash-split issuer holdout of `train` and marked provisional, then measured once on `model_test`, which is the number reported. Design, counts and limits: [04](04-execution-phases.md) 2.4 |
| D17 | Whether the weekly blind run waits for the checkpoint | Weekly blind runs, or all blind runs at the checkpoint | Decided 2026-10-02: "have it wait for the checkpoint so we know that everything is 150% done and correct before freezing it". Consequence: dry runs on the train holdout replace blind runs until then, and the first blind run is part of the checkpoint ([08](08-revised-plan.md), Gates; pool rules in [eval/corpus/README.md](../../eval/corpus/README.md)) |
| D18 | Whether interim (quarterly, half-year) statements get their own pool or are mixed with annual ones in training and scoring | A separate pool, a period sub-split inside the pools, or one stratum recorded and reported | Decided 2026-10-03, raised and delegated by the owner: "would it not be best to split the quarterly into their own area or subsplit so the model doesn't assess them the same in training and later cause unreasonable results?" Not a separate pool, because a company's quarterly and annual statements carry the same labels and splitting them across pools would leak labels (rule 1, R7). Period kind is a stratum recorded and reported on the data, the training weight, every score and the narration. Design: [04](04-execution-phases.md) 2.4 and 2.7 |
| D19 | What the analytics frame is: the pandas `DataFrame` the blueprint sketched in 02 and 04, or a typed `Frame` | A pandas `DataFrame` with float64 columns, or a tuple of typed rows (`Frame`) holding `Decimal` | Chosen 2026-10-05 while building the metric registry, for the owner to confirm: the typed `Frame`. The rows must carry `Decimal` money and the provenance of each cell, which a DataFrame holds only as untyped object columns; the metrics run in `Decimal` and convert to `float` once, so no formula can lose a digit that D6 and the grounding checker depend on; and `fra-analytics` stays free of pandas and pyarrow. The cost: no vectorised operations, which statements of this size do not need. Revisit if a metric ever runs over thousands of periods. The margins are the one exception to the `Frame`: `compute_margins` was built first, over a single income `Statement`, and `compute(statements, policy)` calls it beside the `Frame`-based formulas rather than duplicating it |
| D20 | What Gate A asks of scanned Arabic cells, where no engine or setting has come near G1's 98.0% bar (best 98 of 128, 76.6%, in 7 of 7 runs below it; [14](14-run-profiles.md)) | Keep the 98.0% bar, lower it to another percentage, or replace it with "no wrong figure shown as confident" | Decided 2026-10-13 by the owner: replace it. On scanned Arabic statements Gate A has no cell-accuracy bar. It requires instead that no figure is wrong and shown as confident: every expected figure is right, carries a critical cell flag, sits on a statement held for review, or belongs to a statement that was not extracted. A figure missing from a statement that passed review counts as confident wrong. A pass also requires no confident unassessed numeric output: unmatched or duplicate rows, extra cells or periods, unconfirmed figures and additional statements remain visible in output coverage. Unknown output is not called wrong without a reference, but cannot certify safety. Accuracy and accepted share keep their confirmed-expected-cell denominators; emitted numeric coverage is reported separately. Reasons: the bar cannot be shown at the golden set's size (a perfect 128 of 128 has a 95% Wilson lower bound of 97.1%); the quality of the scans and the variability of Arabic print set a ceiling that no setting has approached; and principle 2 of [08](08-revised-plan.md) (right, or visibly unsure) and Gate E already promise exactly this. Cell accuracy is still measured and reported with its interval, beside the share of figures on statements that passed review, so that a pass obtained by holding everything is visible. Digital cells and English scanned cells keep G1's bars, and G1 in [04](04-execution-phases.md) stays the production target. `make eval-gates` reports the measure (`harness.confidence`). Limits: the scanned Arabic expected cells are one document of one issuer (`edita-2024-ar-consolidated`, 128 cells), so a pass says nothing of other issuers' scans; and the decision was taken after the `dev` results were seen, which is why it is recorded before the checkpoint (D13) instead of being applied silently. Superseded for gate scope by D21; no longer governs a gate |
| D21 | Which languages the remaining gates and demo score | Keep English and Arabic; score English only and report Arabic as measured but not gated; cut Arabic code | Decided 2026-10-21 by the owner: score English only. Arabic stays in the code, training pool and corpus, is reported with measured limits, and carries no gate. D14 and D20 remain on record but no longer govern a gate. Declare language scope before the D13 checkpoint and apply it to the whole pool by document language, never by result |
| D22 | Keep unseen English blind issuers for the rehearsal | Reserve a fixed-hash subset, or find outside-corpus documents on rehearsal day | Decided 2026-10-26 by the owner, before checkpoint results: reserve the first 8 English-scored blind issuer keys sorted ascending by the hex sha256 of `"rehearsal-reserve-v1:" + issuer_key`. Use manifest language (D21), never results; every reserved issuer must have an English document. Record only the rule and issuer keys in `eval/corpus/rehearsal_reserve.yaml`. No reserved document is opened, read or run before rehearsal. Gate E covers the remaining English blind issuers and says so: metadata recount gives 29 documents from 20 issuers, with 10 documents from 8 issuers reserved ([corpus rules](../../eval/corpus/README.md)) |
| D23 | Whether to wait for every planned gate to be measurable before the one-time checkpoint | Delay the checkpoint, or proceed and report limitations honestly | Decided 2026-10-26 by the owner, before checkpoint results: “proceed to the checkpoint and report it honestly.” This supersedes D13's wait for every gate result to be available: proceed with the one-time `model_test` and non-reserved `blind` pipeline observations even though this runner has no reference-answer path and therefore cannot judge Gates A, B or E, and the approved SEC training path restricts Gate C examples to `train`. Validation-panel results remain diagnostics; do not claim any of those gates passed or failed. This decision does not waive checks, the candidate freeze, pool barriers, or the separate Gate D precondition: before step 1 the plan must record successful Docker upload-to-summary results for digital and scanned English documents, or the owner must record a specific Gate D exception. As of 2026-10-26 the plan records neither, so that precondition remains unmet. See [08](08-revised-plan.md) and [the checkpoint runbook](../runbooks/checkpoint.md). |

The owner recorded D21 on 2026-10-21: "let's limit to english only and sideline arabic, its
causing too many problems for the time we have." Uploads whose extracted text is identified as
mainly Arabic are declined with the plain language reason; Arabic OCR, rendering and narration
support remain in the code. This is a text-derived script majority check, not general language
identification: poor OCR can miss Arabic text, and non-English Latin-script reports may be
processed as English. Scanned-page metadata and configured OCR languages do not identify the
report's language. This scope is recorded before the planned 24 October D13 checkpoint and
before protected scoring.

## 6.2 Risk register

| ID | Risk | Impact | Likelihood | Mitigation | Owner work package |
|----|------|--------|------------|------------|--------------------|
| R1 | Scale misread ("in thousands" missed), making every value 1,000x wrong | Critical | Medium | Multiple signals (caption, header, page text, magnitude sanity check against sibling statements); conflicting signals block with `scale_conflict` | V4, T1 |
| R2 | Value columns shifted against period headers, usually around a "Notes" column | Critical | Medium | `header.py` detects note-reference columns; column x-ranges checked against header bboxes | V2 |
| R3 | Statement continues on the next page and rows are lost or duplicated | High | Medium | `continuation.py` merges by header signature and column geometry | V6 |
| R4 | Swap thrash when both heavy runtimes load at once on 18 GB | High | High without controls | Heavy lease, session profiles (dev unloads between jobs), `memory_guard`, preflight before demo and training runs | V10 |
| R5 | Disk exhaustion (44 GB free) | High | Medium | Section 01, 1.4 budget; `make disk-report`; LRU pruning of `var/store` | V10 |
| R6 | mlx-lm silently truncates long training examples | High | High | `length_audit.py` fails the build when any example exceeds `max_seq_length` | T10 |
| R7 | Train and test leakage because the same company appears across years | High | High | Group split by entity (CIK or registry id) before any other split | T10 |
| R8 | Fluent narrative with numbers that match no computed metric | Critical | Medium | Grounding checker, one regeneration, deterministic template fallback | V9, T8 |
| R9 | Upstream drift (docling releases often) | Medium | High | Exact pins in `uv.lock`; upgrades must pass `eval/thresholds.toml` gates | T11 |
| R10 | MLX or PyTorch MPS regression on macOS 27 | Medium | Low | Phase 0 smoke tests; pinned versions | V10 |
| R11 | Bank or insurer statements forced into the corporate template | High | Medium | Classifier detects financial-institution line items; D7 routing | V7 |
| R12 | Golden set documents with unclear usage rights | Medium | Low | Public regulatory filings only; source and retrieval date recorded in `eval/golden/manifest.yaml` | V1 |
| R13 | Arabic OCR quality, right-to-left column order, Hijri period headers | High (Phase 4) | High | Phase 4 spike before commitment; logical CSS properties and locale hooks in place from Phase 1 | Phase 4 |

## 6.3 Repository hygiene

1. **Own git root.** This directory currently sits untracked inside a parent repository.
   Phase 0 runs `git init` here and adds this directory to the parent's `.git/info/exclude`.
2. **Local state stays local.** Editor and cache directories go in `.git/info/exclude`, not
   `.gitignore`. The committed ignore file lists only project paths (`var/`, `.venv/`,
   `node_modules/`, training data and adapter weights).
3. **Audit.** V11 checks the above before every tagged release.
